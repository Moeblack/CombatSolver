> 当前基线：`0.14.13`（2026-08-28）

## 0.14.13：Loadout 战斗费用兼容

- 最新实机日志在创建首回合搜索根时拒绝了 Loadout 新增的 `LoadoutEveryCardFreeCombatHook`，因此界面显示“搜索初始化失败”。Legacy RNG 兼容层和 CombatSolver 本身均已成功初始化，首个错误只发生在未知 gameplay subscriber 的根快照校验。
- 根快照现在按玩家捕获 Loadout 的“所有牌免费”状态，搜索分支从该不可变值修正能量费用。开关关闭时不会再因订阅者存在而拒绝搜索；开关开启时，当前卡牌和后续生成卡牌都按 Loadout 的 0 费规则计算，worker 不读取 Loadout 的实时静态状态。其他未知 gameplay subscriber 仍保持显式拒绝。
- 实际 Loadout `0.4.10` 与 BaseLib `3.4.5` 的第一轮定向运行已经成功创建并 Fork 根快照，原 `SEARCH_SETUP_FAILURE` 未再出现；运行随后暴露测试对 ModHelper 运行级订阅者的旧计数口径并已修正。修正后的第二轮在 Loadout 的 headless 战斗房间资源预载处超时，未进入断言，因此不记为完整场景通过。

## 0.14.12：牌堆压缩后的连锁路线

- 同族小队极限存档的生还路线依赖怀表控牌、灰水一次耗尽六张手牌，以及下一回合按“愤怒复制 → 放血回费 → 燃烧契约抽牌 → 多段攻击”完成斩杀。旧搜索会把这些中间状态分别压回即时伤害最高的代表，导致完整连锁在伤害兑现前被淘汰。
- 多张选牌现在为每个合法选择数量保留代表，选牌历史按来源、效果、具体选项和当前回合事件隔离；错误的选择分支直接淘汰。牌堆状态同时区分精确敌方分布、无序牌堆构成和有序洗牌前缀，避免不同灰水/燃烧契约选择被错误合并。
- 怀表边界显式保留出牌节奏、目标集火和若干精确洗牌状态。大规模回合末牌堆压缩会建立持续到后续回合的专用路线血统，并分别保留回费、攻击复制增长、牌堆整理、集火、进攻和下一步动作种类；这让零费铺垫、回费和抽牌可以在终结伤害出现前连续存活。
- 易伤的中间价值改为按可利用的攻击窗口非线性计算，当前能量作为能否继续出牌的独立 Beam 资源；两者只影响中间保路，最终路线仍按真实胜负、战损、药水和卖血规则选择。
- 精确回归 `kin-boss-route-clean` 从 56 HP 开始，第 5 回合以 3 HP 获胜，战损 53，计划外重算为 0。最终路线第 4 回合使用灰水压缩牌堆，第 5 回合通过愤怒、放血、燃烧契约和连续攻击击杀三名敌人。

## 0.14.7：Beam 检查点回收与跨战斗后台回收

- 实机历史日志确认战斗 Reset 曾同步执行强制、阻塞、压缩式全代 GC，单次暂停约 `177-382 ms`；高水位时还调用 `EmptyWorkingSet`，把整个游戏工作集从约 `3.28 GB` 降到 `101 MB`，直接制造后续房间的重新缺页。该路径已经删除，战斗结束只登记后台非压缩全代回收，不再清空进程工作集。
- 回收请求现在与真实 worker 生命周期绑定。取消或异常的搜索即使晚于战斗 Reset 退出，也会在最后一个 worker 退出后完成已登记回收；下一场搜索等待回收任务完成，避免压力状态跨战斗遗留。
- Runtime 依据 No-GC 的 SOH 可用额度注入分配边界。搜索只在一层出牌扩展完成、当前 Beam 已剪枝的安全点响应：保留活动 Beam、已完成候选和路线父链，丢弃转置表、已展开表及可重建评分缓存，结束本轮 No-GC，等待后台非压缩全代回收完成，建立新 No-GC 配额，再从原 `turn_layer/play_depth` 继续。该机制不提前返回路线，也不从战斗根重算。
- 1 GB 压力场景 `GC-CHECKPOINT-RESUME-0147`（runId `cd3b633d60754b5cad509fe3c175bbc7`）触发 `5` 次检查点；每次保留 `30` 个活动节点，回收后托管存活量从约 `659-806 MB` 降到 `100-205 MB`，GC 暂停为 `3.1-4.0 ms`。最终搜索到完整 `6` 回合路线并获胜，`UnexpectedReplans=0`，没有 No-GC 耗尽、`>50 ms` 主线程帧或提前内存边界。

## 0.14.2：单步回合边界与重放卡牌身份

### 单步与全自动的控制边界

- “执行本回合”只部署当前回合路线。上一回合结束后，后续 `SetupPlayerTurn` 不再消费计划中的必备工具、暴政等回合开始选择；原版页面保持打开并等待玩家。只有全自动模式会在该页面按上一轮 `EndTurn.TurnStartChoices` 播放既有计划。
- 全自动完成回合开始选牌后，`PlayerTurnSetupCoordinator` 先结束并释放当前原生选牌会话，再恢复 continuation 或启动剩余路线部署。这样嵌套部署不会压在旧会话之上，消除了 `turn_setup:N` 不是活动栈顶的异常；页面仍是动画展示，不触发新搜索。

### 同名卡牌的语义身份与 Beam 保路

- `PlanCardToken` 记录卡牌语义状态键。部署与预测回放按 ID、升级、费用、重放次数、临时标志、关键词、动态变量、附魔和苦难状态匹配具体实例；带螺旋附魔的重放防御与普通防御不再被当成可互换的同名牌。
- `BeamRetentionPolicy` 的选牌保路覆盖动作选择、嵌套选择和 `EndTurn.TurnStartChoices`，并纳入弃牌/弃牌再抽。不同来源、上下文和卡牌语义状态的路线各自保留候选，避免必备工具的弃牌分支在后续出牌价值显现前被同一 Beam 层淘汰。
- 定向 headless runId `07d96613e313442a99275ee969e1c02b` 证明单步在第 2 回合手牌页停住、求解器选择次数为 0，并计划弃掉普通防御、保留带螺旋附魔的防御。全自动 runId `80552c268daf450cbce05aeb9314b844` 在同一牌组上记录 `visible=1 / selected=1 / search=0`，第 2 回合直接续用且计划外重算为 0，日志中没有原生选牌会话栈异常。
- 玩家问题包只保存了必备工具选择完成后的检查点，且没有通用逐实例战斗状态导入器，因此不能从包内状态精确还原选择前的第 3 回合手牌；上述定向夹具隔离验证了同名普通/螺旋防御的计划身份和两种控制模式，不把非精确复现写成原问题整战复现。

## 0.14.1：原生选牌界面与路线复用

### 原生选牌界面与回合准备边界

## 1. 项目目标

CombatSolver 只解决一场已经开始的单人战斗：读取当前战斗状态和可预测 RNG，在不修改游戏 RNG 的前提下，以时间和节点预算搜索较优行动路线，并允许玩家查看或自动执行当前回合方案。

当前不讨论整局路线、选事件、商店、地图和构筑。开发回归通过隔离的塔 2 `--headless` 进程执行原版规则，不另建自有 CLI。

设计优先级：

1. 路线能在原版战斗中执行。
2. 已知效果尽量与游戏结算一致。
3. 未镜像内容必须显式记录，不能用“高置信度”掩盖。
4. 搜索在后台运行，不阻塞游戏主线程。
5. 性能优化不得悄悄改变 RNG 或把近似搜索描述成穷举。

## 2. 当前功能基线

### 搜索

- 两阶段 Beam Search：短搜统一宽度 `12`，深化统一宽度 `30`；药水不再拥有独立配额。
- 默认中档短搜预算 `5 秒 / 1200` 节点；短结果存在未来掉血、用药或未确认胜利时，同一搜索会话继续使用总计最多 `60 秒 / 6000` 节点的深化预算。
- 回合内行动数不设上限。费用、星能、可出牌性、击杀、完全状态循环剪枝、时间和节点预算共同构成终止条件。
- 不设固定回合数或洗牌次数上限；时间、节点、确认胜负和可证明循环构成搜索边界。
- 每节点短搜最多保留 Top-10 出牌分支，深化最多 Top-16；深化同时扩大牌堆/手牌选项预算。
- 子节点保存生成时的模拟快照；后续展开、最终复核和路线标注复用快照。
- 最优路线会保存后续玩家回合的预测起点；真实状态逐项文本一致时直接复用剩余路线，状态不一致则重算。手动按 `I` 始终强制重算。
- 相同状态下的等价重复卡牌只模拟一次。
- 每次 Beam 剪枝除评分最高路线外，还保留一条当前威胁下预计剩余生命最高的防御路线，使回合结束时的最低可达到战损基线不会被输出评分提前挤掉。
- 深化搜索额外保留成长、资源、控制和帕累托路线，并对非即时效果执行一次缓存的结束回合探测；不按具体牌名特化毒伤或蛇咬。
- 同一搜索会话复用“父状态 + 动作”的模拟转移。完全相同状态继续由置换表剪除；零资源且出牌后回到同一手牌实例的动作若连续不改变敌方生命、双方资源、玩家生命或手牌数量，则按无进展循环单独计数，基础保留 `16` 次。循环造成伤害后立即重新计数；手中存在全身撞击、月华冲击、金斧等线性击杀兑现牌，或敌人带缓慢且手里有攻击牌时，保留范围扩大到当前敌方有效生命，避免把可击杀无限构筑误剪。该机制不限制普通回合行动数。
- UI 在滚动框中展示本次搜索得到的全部回合；完整路线同时写入日志。

### 选牌

- 支持从手牌、抽牌堆和弃牌堆选择已有牌，以及移动、弃置、消耗、升级等已列入支持表的选择。
- 正在结算的头槌等卡牌不会提前进入自己的弃牌堆候选。
- 富足、发现、类星体和飞溅的生成三选一已进入搜索分支；部署器可直接驱动原生“选择一张牌”界面。药水、回合开始选择和嵌套自动出牌使用同一计划令牌，不等待玩家干预。
- 现有牌选择统一由 `CardChoiceSpec` 描述；必备工具等回合开始选择、普通出牌选择、生成选项和嵌套自动出牌共用计划令牌与部署选择器。
- 当前选牌不是全部穷举：单卡捞取枚举所有不同结果；多牌组合的牌堆选择最多保留 `4` 个启发式优先分支，手牌选择最多保留 `6` 个。
- 这个限制会提高速度，但可能漏掉面板价值较低、后续联动较强的候选，属于明确的精度取舍。

## 3. 当前评分语义

最终路线不再只按线性 `Score` 选取，而是依次比较：玩家存活、确认胜利、整场预计掉血、药水数量、累计主动卖血、敌方剩余生命和行动数量。动态重搜或未支持边界不能冒充确认胜利。普通药水路线若能取得无药路线做不到的确认胜利可直接进入比较；否则仍须相对最佳无药路线每瓶至少省下 `9 HP`。龙涎香不适用胜利直通：无论药水模式如何，都必须相对最佳无药路线最终多保住至少 `ceil(最大生命 × 40%)`，同时使用的其他药水成本继续叠加。

Beam 中间排序与最终选择分离。稳健预设把 `1 HP` 约视为 `3` 点即时伤害，用于避免长线保血路线在到达终点前被即时输出挤掉；能力牌铺垫奖金只在当前回合内帮助展开，结束回合后清零，后续价值必须由模拟出来的 Power、牌序和伤害证明。未用能量不再单独扣分。普通出牌与药水共同竞争统一 Beam，快搜/深化默认宽度为 `12/30`；剪枝仍强制保留最佳无药、无药防御、无药进攻、无药策略和一个药水安全候选，因此药水不会抹掉最终收益比较所需的无药反事实基线。

默认中档使用 `5` 秒短检查点和 `60` 秒总预算。短结果仍会新增战损、使用药水或没有确认胜利时，同一搜索会话继续深化；长预算是上限，搜索空间提前耗尽会立即返回。

扣血与主动卖血按整场战斗累计，不会在新回合归零。对同一个回合起始状态，搜索器先比较所有已经完整结算该回合、且没有停在动态或未支持边界的候选，以其中最低可达到战损为基线；某条路线超过该基线的实际掉血才算主动卖血。这样既包含少出防御，也包含放弃击杀、虚弱等其他可用减伤手段。直接击杀且未掉血不计卖血，根本防不住的伤害也不计卖血。主动卖血阈值为普通 `5`、精英 `10`、Boss `15`；阈值是整场战斗硬预算，搜索每完成一个回合就剪掉累计超额路线。

重要规则：战斗已经结束后，能力牌不再获得未来回合收益。`0.5.8` 曾因此错误选择第三回合先打能力牌再斩杀，而不是第二回合直接斩杀；`0.5.9` 已修正。

## 4. 代码结构

- `src/Search/`：搜索循环、计划与快照、选牌、模拟状态、预算和后台步调。
- `src/Prediction/`：怪物意图、牌与 Power 补偿、怪物行动效果和覆盖分类。
- `src/Engine/`：内置并独立命名的最小战斗模拟核心；只保留状态、牌堆、RNG、分叉、历史和战斗 Mirror，不含 RF 的入口、补丁、UI、设置、遥测与局外功能。
- `src/Runtime/`：Mod 入口、异步生命周期、状态文本、自动部署与结构化日志。
- `src/Testing/`：原版游戏进程中的一次性无人测试协议、场景执行器与进度隔离补丁。
- `src/UI/`：Godot 覆盖层 UI。
- `docs/`：持续开发笔记与外部审计材料。
- `tools/run-unattended-test.ps1`：直接启动使用独立用户目录、关闭 Steam 的 `--headless` 游戏进程，并等待同一 `runId` 的结构化结果；检测到玩家进程时拒绝启动。
- `tools/CoverageCatalog/` 与 `coverage/`：稳定编号的战斗钩子目录、分类和完整性检查。
- `local.props.example`：本机依赖路径配置示例；真实 `local.props` 不进入版本控制。

## 5. 性能现状

已完成：

- 搜索节点复用模拟快照。
- 节点去重与等价卡牌判断使用双 `ulong` 状态指纹，避免为每个状态创建长字符串；跨回合续用仍使用完整状态文本，不依赖指纹。
- 跨回合复用已选路线：逐项比较生命、格挡、费用、各牌堆、Power、怪物意图与相关 RNG 计数，不做哈希；完全一致时下一回合为 `0` 个新展开节点。
- 后台线程使用较低调度优先级；每 `16` 次回放检查一次连续工作时间，超过 `4 ms` 时调用 `Thread.Yield()`；搜索进度改用普通 `Label` 并限制为每 `200 ms` 最多刷新一次。
- 自动搜索至少延迟三个渲染帧，并等待游戏的回合开始动作队列执行完成，避免与发牌、状态结算的峰值直接重叠。
- 模拟状态中未使用的 Power/回合资源/怪物专项集合按需创建；状态剪枝、动作支配与 Top 队列避免构造 LINQ 中间分组。
- 怪物模型的反射数值访问器按类型和成员缓存为编译委托。
- 最终候选、战损、击杀和战斗结束标注不再重复完整回放。
- 合并等价重复卡牌与重复选牌组合。
- 选牌使用独立局部分支预算。
- 日志记录 `expanded`、`replays`、`snapshot_reuses`、`duplicate_cards_pruned`、`choice_branches`、后台线程分配量、每次回放平均分配、GC 次数、搜索区间 GC 暂停和线程让步次数。GC 次数与暂停是进程级区间数据，不能单独归因给求解线程。
- `0.7.6` 的真实跑局快照路线质量回归需要 `2542` 次完整回放、约 `5.99 GB` 工作线程分配和 `22.4 s`；结果正确但性能不合格。扩大 Beam 不是 GC 解决方案，下一阶段仍需 RF 提供可靠的模拟器分叉/深拷贝，或由本模组实现可分叉模拟内核。
- `0.8.0` 已在本地 RF fork 中加入完整模拟状态分叉 API：根状态只构造一次，每个搜索候选从父节点复制 RNG、牌堆、逐牌状态、Orb、生物、历史、RF StateStore 以及求解器自有 Power/遗物状态，再只执行当前动作。搜索节点改为父链保存单个动作，不再为每个分支复制整条动作列表。长线固定快照的 `2541` 个分叉逐一与旧完整前缀回放比较，状态文本、指纹、边界、风险和 RNG 全部一致；实机仍为第 `6` 回合结束、`0` 战损、`0` 药损。三次干净进程性能中位数为 `605,129,120 B / 2.394 s / 505.6 ms GC 暂停 / gc2=0`，相对 `0.7.6` 的 `5.99 GB / 22.4 s / 10.42 s GC 暂停` 分别降低约 `89.9% / 89.3% / 95.1%`，通过 `0.9 GB / 5.6 s / 暂停降低 80%` 门槛。原始三次指标和计算口径见 `docs/RF_FORK_PERFORMANCE_RESULTS.md`。
- `0.9.0` 在 RF fork 上继续加入卡牌预览写时复制、StateStore 按键惰性复制、共享历史前缀、求解器私有集合写时复制、原生 Hook 监听器分支缓存和无序列化 RNG 克隆。短搜/深化预算改为 `3/20` 秒，深化使用 `24+8` Beam、扩大选牌预算、帕累托路线和通用延迟收益探测；短结果有战损、用药或未确认胜利才触发。回合内行动上限删除，完全相同的无进展状态负责循环终止。最终长线差分比较 `2540` 个实际转移全部一致；8 张零费小刀在同回合全部执行并击杀。

## 6. 已知限制

- 牌堆选牌为 Top-K 近似，不是穷举。
- 搜索不再因洗牌次数、空牌堆或固定回合数停止；极端无胜负循环最终由时间或节点预算终止。
- 多人牌、多人模式和局外效果仍不在本项目范围；游戏版本新增而目录尚未收录的行为必须重新审计。
- 部分动态怪物伤害仍为近似值。
- 当前 `0.111.0` 目录内单人战斗钩子已完成分类与证据闭环；游戏更新后的新增行为仍需重新生成目录和审计。
- 瀑布巨兽被提前击杀后的无限生命显示、蓄爆与爆炸自灭已加入模拟，并通过 `MONSTER-WATERFALL-001` 可见游戏场景验证；其普通行动中的动态伤害仍按现有近似策略标注。
- 状态键和等价卡牌键需要随着新实例状态的支持持续补充。
- 当前只支持单人战斗。

## 7. 未来构想：RitsuLib 路径预设

搜索预算和 UI 位置已经由模组自身 JSON 设置页实现。这里保留的未来项只指改变最终目标权重的“路线风格预设”；此功能尚未实现。

初步预设：

### 短期保血优先

- 提高近期生命与格挡权重。
- 降低主动卖血容忍度。
- 降低为了未来回合而提前打能力牌的收益。
- 适合普通战斗、低血量或只关心眼前一至两回合的情况。

### 长线能力优先

- 提高能力牌与持续状态在剩余已知回合内的价值。
- 允许在阈值内承受少量战损换取后续收益。
- 仍必须在终局清空未来收益，不能为了“已经不存在的后续回合”延迟斩杀。

### 均匀伤害优先

- 提高 AOE 和敌方总生命下降的权重。
- 降低对单个低血目标的过量伤害。
- 可能适用于需要同步压血或后续有群体斩杀的场景，但面对高威胁单体时未必合理。

### 减员优先

- 增加存活敌人数惩罚和提前击杀奖励。
- 优先消灭能行动、成长或造成高威胁的目标。
- 避免把伤害平均铺开却让所有敌人继续行动。

### 建议的配置结构

不要直接在运行时修改 `SolverWeights` 常量。更合适的结构是：

1. 定义不可变 `SolverProfile`，包含评分权重、卖血阈值、搜索预算、选牌预算和边界策略。
2. 通过 CombatSolver 自身的持久化设置保存 `PresetId`，并允许高级用户覆盖少量关键参数。
3. 每次发起搜索前在主线程捕获一份完整配置快照，后台线程只读取该快照。
4. 日志写入 `preset`、配置版本和所有覆盖项，保证结果可以复现。
5. UI 中显示当前预设，但不要让预设名称代替实际权重日志。

预设不是“难度档位”，而是不同优化目标。它们应共享同一套模拟规则，只改变评分、预算和剪枝偏好。

## 9. 原版规则验证与无人闭环

- 开发流程通过 `tools/run-unattended-test.ps1` 直接启动塔 2 自带的 `--headless` 进程；它仍运行原版游戏程序集和动作队列，不是自建 CLI 或重写规则。
- 无人进程使用 `%LOCALAPPDATA%/CombatSolver/headless-runtime` 下的独立 `APPDATA/LOCALAPPDATA`，通过 `--force-steam=off` 避免 Steam 会话，并在隔离设置中显式允许 Mod 加载，绕过无界面的首次 Mod 警告确认。由于关闭 Steam 后游戏不扫描创意工坊，启动器只在 headless 生命周期内把当前游戏版本的 RitsuLib 投影到带所有权标记的本地临时目录，进程退出后删除；不会复制 RF 或其他创意工坊 Mod。脚本只复用 marker 明确记录的测试 PID；发现任何其他塔 2 进程时立即拒绝启动，不与玩家进程并发。
- 一次性请求先写入同目录临时文件，再原子发布为 `user://combat_solver_test_request.json`，避免游戏读取半写入或被占用的请求。Mod 建立 `shouldSave:false` 的单人跑局，进入指定遭遇，通过原版 `CreatureCmd`、`CardPileCmd` 和动作队列注入状态，再调用求解器全自动。
- 测试结果写入 `user://combat_solver_test_result.json`，必须以同一 `runId` 匹配；成功场景会清理跑局并回到主菜单，默认保留进程供下一场复用，只有最后一场显式要求时才退出。
- 无人测试期间跳过原版 `UpdateProgressAfterCombatWon`，避免把测试遭遇和击杀写入玩家进度。首轮验证在加入隔离前已经把一次毛绒伏地虫胜利写入当前 Modded Profile；这次历史修改无法在没有事前快照的情况下可靠回滚。
