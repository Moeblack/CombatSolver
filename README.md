# 战斗路线求解器

源码仓库：[Torch1230/CombatSolver](https://github.com/Torch1230/CombatSolver)。第三方代码来源与书面许可见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。当前仓库已经公开源码；统一的软件许可证将在 Random Foreseer 后续许可证明确后补充，在此之前不要把公开可见误解为未受限制的复制、修改或再发布授权。

当前源码职责地图见 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)。开发过程、当前限制和未来路径预设构想见 [docs/DEVELOPMENT_NOTES.md](docs/DEVELOPMENT_NOTES.md)。逐项覆盖见 [docs/COMBAT_HOOK_COVERAGE.md](docs/COMBAT_HOOK_COVERAGE.md)，每个求解器自有适配的中文预期与测试闭环由开发者手工维护在 [docs/ADAPTATION_VERIFICATION.md](docs/ADAPTATION_VERIFICATION.md)，待测场景见 [docs/TEST_MATRIX.md](docs/TEST_MATRIX.md)。外部审计原文及处理结论见 [docs/AUDIT_REPORT.md](docs/AUDIT_REPORT.md) 与 [docs/AUDIT_RESPONSE.md](docs/AUDIT_RESPONSE.md)。

适配《杀戮尖塔 2》`0.111.0`。依赖：

- STS2-RitsuLib `0.5.13`

Combat Solver 的内置战斗模拟核心使用并改造了 Random Foreseer 的部分实现，现已获得原作者 hotwords123 的许可。相关来源关系持续存在于当前版本，涉及战斗状态、牌堆、RNG、Fork、History 和 Mirror 等基础逻辑；Combat Solver 在此基础上持续重构并扩展了跨回合搜索、路线复用、自动执行、原生选牌和性能控制。Combat Solver 不引用或部署 Random Foreseer 程序集，两者没有 manifest、程序集或补丁依赖；这项运行时分离不改变上述代码来源关系。Linux 下完整本机构建使用 `./tools/build-local-stack.sh`；脚本默认使用标准 Steam 路径，其他库位置通过 `SteamRoot` 或 `local.props` 覆盖。原有同名 `.ps1` 保留供 Windows 使用，原生 `.sh` 不调用 PowerShell。

进入单人战斗后，每个玩家新回合会在发牌与回合开始动作队列稳定后自动启动后台搜索。搜索视野不设固定回合数或洗牌次数上限，由时间与节点预算终止；第一回合算出的后续路线会保留，新回合状态与预测起点逐项一致时直接复用，任一项不同才重新搜索。搜索线程使用较低优先级并周期性让出 CPU。长搜索使用跨本场战斗的 No-GC 区域，默认总预算为 8GB，战斗退出后才统一结束区域并压缩托管堆。回合末只分叉确实带临时费用、保留、伶俐或耗尽状态的牌，已展开和被 Beam 淘汰的历史节点会释放完整 Simulator。零资源且出牌后回到同一手牌实例的动作若连续不产生敌方进展，会按循环分支剪枝；实际伤害会重置计数，依赖格挡、出牌数或缓慢的击杀兑现会扩大保留范围，因此不会恢复普通回合行动数上限。覆盖层可拖动，路线滚动框展示本次搜索所得的全部回合；搜索状态使用固定列和秒计时，当前预算内没有生还候选时会明确标注。最终路线胶囊会列出钢笔尖、佩尔之眼等实际触发的遗物联动；直接结束触发佩尔之眼时标在“直接结束”胶囊内，带重放的卡牌在牌名后显示“重放×N”，击杀胶囊以绿色显示并写明击杀对象。自动执行时，回合开始选牌胶囊只显示已经完成的准备动作，不占用出牌进度；当前牌在实际动作启动时高亮，结算完成后立即变暗，牌间停顿不会提前点亮下一张。“重新计算”会从当前实机状态发起新搜索，“执行本回合”只执行当前回合，绿色“全自动”按钮会连续搜索、执行并结束回合。搜索期间“执行本回合”会变为红色“停止计算”；停止后本场后续回合不再主动搜索，直到玩家点击“重新计算”。单步结束后的回合开始选牌页默认等待玩家；在该页面点击“执行本回合”或开启全自动会接管既有路线选择并直接复用，不从选牌中间态重算。设置中的牌间额外停顿也应用于回合开始选牌到第一张牌。若计划执行到中途时原版游戏判定下一张牌已经不可打，部署器会记录真实资源、目标和阻止来源，从当前实机状态自动重搜，不再直接中止。全自动打完计划牌后、提交结束回合前还会按此刻实机怪物、Power、格挡、意图和原版额外回合判定复核本轮风险；若将死亡或掉血高于路线预计，则保留玩家回合并暂停。手操偏离后，求解器会记录重算前后的整场预计战损；若玩家找到更低战损路线，界面会用绿色提示建议导出完整问题包。设置页分为“基础与执行设置”和“搜索策略配置”，性能可选低档、中档、高档、极高或自定义；时间、Beam、节点、出牌分支和 No-GC 预算均提供悬停说明，手动修改任一算力数值会自动切换为自定义并持久化。新安装和恢复默认使用中档，死亡回合暂停与“完整路线重算后战损增加时暂停”开启、战斗结束暂停关闭；默认跟随游戏速度且不增加牌间停顿。详细诊断日志默认关闭，可按需开启；“导出问题包”会把游戏日志、截图、存档、当前战斗精确状态、路线和求解器设置打包到桌面 `CombatSolver-BugReports`。战斗结束、放弃或退出后会关闭全自动并隐藏覆盖层。Mod 不会改动游戏 RNG。

当前模型会实际推进：

- 当前手牌效果（使用 CombatSolver 内置战斗 Mirror）
- 抽牌堆、弃牌堆和预算范围内任意次数可预测洗牌的牌序
- 能量重置
- 怪物 `MonsterAi` RNG 与行动状态机
- 攻击意图造成的逐段伤害和格挡
- 玩家施加的力量、敏捷、虚弱、易伤、中毒，以及下回合能量
- 一批常见怪物行动施加的力量、虚弱、易伤、脆弱
- 附魔的确定性伤害、格挡、费用、重复次数、一次性与私有成长状态，以及等离子球的回合开始能量
- 会召唤、逃跑、替换怪物、改写牌库或改变后续 AI 私有状态的怪物行动；分支自有阵容、稳定 CombatId、怪物 AI 状态日志和相关 RNG 一同推进
- 噬尸蛞蝓的饥饿死亡联动：同伴死亡后获得力量并跳过下一次行动；最后一只死亡可确定结束战斗
- 中毒触发与核心持续时间递减
- 抽牌数、最大能量、跨回合保留格挡和整手保留使用游戏原生纯计算钩子，并读取当前搜索分支中的有效 Power 状态
- 独白、湮灭及一组临时 Power 的出牌配对、精确实例移除、回合末计数重置和施加者死亡清理
- 从手牌、抽牌堆、弃牌堆选择已有牌，并在自动部署时完成相同选择
- 完整预测武装的格挡、未升级版单牌升级选择，以及升级版全手牌升级
- 补偿愤怒的确定性复制、战斗专注的禁止抽牌、绯红披风每回合开始触发的自伤与格挡（自伤只在再次打出该牌时增加），以及上勾拳的虚弱/易伤
- 补偿瀑布巨兽的蒸汽积累、虚弱、治疗、压力炮成长、蓄爆与爆炸行动；提前击杀后的无限生命显示、蓄爆、爆炸自灭已经由 `MONSTER-WATERFALL-001` 可见游戏场景验证
- 头槌等弃牌堆选牌效果按原版结算时序构造候选，正在结算的牌不会提前进入自己的候选列表
- 普通出牌与药水路线共同竞争统一 Beam，内部同时保留无药基线、保血、进攻、成长、资源和控制分支；敌方永久减力量与虚弱在实际伤害出现前也会保留代表路线，等价重复牌继续合并

生成候选牌、自动出牌、额外回合、召唤/复活/替换怪物、药水槽变化和会改写私有 AI 状态的行为都在搜索分支内继续推进，不要求玩家选牌，也不依赖原生结算后重扫。已有牌选牌会合并效果相同的重复卡牌；单卡捞取会枚举全部不同结果，多牌组合仍按快搜/深搜的牌堆与手牌分支预算保留启发式候选。当前 frontier 节点会保留生成时已经得到的模拟快照，后续展开直接从父状态 Fork；祖先节点只保留动作与标量摘要。覆盖目录当前为 `3035` 项，未分析、待实现和 `NativeAutoRescan` 均为 `0`；逐项列表由 [覆盖报告](docs/COMBAT_HOOK_COVERAGE.md) 自动生成。多人牌、多人模式、局外效果、测试模型和废弃占位符不在范围内。运行时若遇到目录外的新版本效果，仍会以未支持边界停止，不能把它误报为胜利。

最终选路依次比较生存、确认胜利、整场战损、药水、主动卖血和敌方剩余状态，不再让一个线性总分同时决定所有目标。Beam 的中间排序按稳健预设把 `1 HP` 约视为 `3` 点即时伤害；能力牌铺垫只帮助当前回合通过剪枝，进入下一回合后必须由真实模拟状态证明收益，未用能量不再单独扣分。低档为 `5/60s、12/30 Beam、1200/6000 节点、10/16 出牌分支、6GB No-GC`；默认中档为 `8/120s、18/45、2400/12000、14/24、8GB`；高档为 `12/180s、24/60、5000/25000、20/32、12GB`；极高为 `20/300s、36/90、10000/50000、30/48、16GB`。药水不使用独立 Beam，按稀缺资源机会成本参与中间排序，并保留必要的药水安全候选与无药反事实路线。药水最终仍须取得无药路线做不到的确认胜利，或每瓶至少节省 `9 HP`。扣血与卖血按整场累计，普通/精英/Boss 的卖血硬阈值为 `5/10/15`。第一、二幕 Boss 和第三幕第二 Boss 胜利后会恢复生命，因此这些战斗降低剩余生命与主动卖血的中间权重、放宽卖血预算，并在确认胜利候选间优先保存药水；第三幕第一 Boss 仍使用普通 Boss 生存策略。

开发回归可运行 `./tools/run-unattended-test.sh`。脚本默认直接启动隔离的塔 2 `--headless` 进程，使用独立 XDG 数据目录、关闭 Steam、将测试内游戏速度设为 `Instant`，并拒绝与交互式游戏进程并发；同一版 DLL 的多个请求会复用一个进程。参数 `--verify-incremental-search` 会让每个候选同时执行增量分叉和旧完整回放并逐字段比较，仅用于正确性验证，不用于性能计时。`./tools/run-visible-steam-benchmark.sh` 通过 Steam 启动正常可见游戏，用固定机甲快照验证真实渲染进程的搜索耗时、GC 和帧间隔，并在测试后恢复请求/结果文件。
